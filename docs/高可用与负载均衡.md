# 高可用、保活与负载均衡

ComputeDeck 的高可用分三层：推理入口（Edge / AI Gateway）、Job 保活（watchdog）、控制面进程（systemd）。  
默认路径很直接：入口用 Edge；AI Gateway 就绪后会随入口一起启动；启用了默认 Job 的 watchdog 会自动保活。

## 1. 推理入口与负载均衡（Edge）

![推理入口：客户端 → Edge → 健康端点池，可选 LiteLLM](assets/edge-ingress.svg)

Edge 默认能力：

- 从 `state/endpoint_health.json` 选健康上游；健康数据尚未就绪时使用全部端点；
- `strategy`：`round_robin`（默认）/ `least_conn`（按在途请求数）；客户端 LB 片段还支持健康优先/按节点；
- `retries` + `cooldown_sec`：连接失败换下一个上游，失败上游短暂冷却；
- 健康检查入口：`/_gpu_control/health`。

相关配置（`cluster.gateway.ingress`）：

```json
{
  "enabled": true,
  "bind": "0.0.0.0",
  "port": 18080,
  "kind": "edge",
  "strategy": "round_robin",
  "retries": 2,
  "cooldown_sec": 30,
  "connect_timeout_sec": 2,
  "read_timeout_sec": 300
}
```

查看/运维：

```bash
gpu-control gateway status
gpu-control gateway ensure          # 渲染产物 + 拉起 Edge（+ 可用时自动拉起 AI Gateway）
gpu-control endpoints --refresh    # 刷新入口健康
```

## 2. AI Gateway（LiteLLM）默认策略

- Edge 是主入口；LiteLLM 是 **可选增强**，不需要用户二选一。
- 当 `litellm` 二进制或 `gateway.openai_proxy_dir/start_litellm.sh` 就绪时，
  `gateway ensure` / `gateway start` 会**自动**把它作为 companion 启动；
- 未安装时不影响 Edge，看板显示 “未配/未安装”，不会把入口判为故障；
- 运行状态、端口、配置、日志见 `gateway status` 与看板「AI Gateway」。

```bash
gpu-control gateway ensure
# 显式只启 AI Gateway（调试用）：
gpu-control gateway start --kind litellm
```

## 3. Job 保活（watchdog）

watchdog 定期对 Job 执行 `status`，不健康时 `restart` + `wait`：

```json
"watchdog": {
  "enabled": true,
  "jobs": [],
  "interval_sec": 60,
  "max_restarts": 3,
  "failure_threshold": 2,
  "nodes": "all"
}
```

- `jobs` 为空时使用 `default_job`；
- 默认**连续 2 次**不健康才重启，避免一次网络抖动就重启线上服务；
- 健康检查成功会**清零**重启计数，后续故障仍有完整预算；
- 被隔离节点会被跳过；
- 状态：`state/watchdog.pid`、`state/watchdog_state.json`、`state/watchdog.log`；看板「自动重启」行。

```bash
gpu-control watchdog --background
gpu-control watchdog --job sft --interval 30 --once   # 单轮检查
systemctl status gpu-control-watchdog                  # 生产建议 systemd
```

> watchdog 只负责“进程/服务活着”；训练是否收敛、推理是否可服务要看 Job 自己的 `wait` 契约
> （`vllm-serve` 会做 HTTP/TCP 就绪检查）。

## 4. 控制面进程保活

生产建议用 systemd（见[生产部署](生产部署.md)）：

```ini
Restart=on-failure
RestartSec=3
```

UI 支持 SIGTERM 优雅退出并清理 pid；Edge/LiteLLM 的 pid 文件由 gateway 管理。
控制面按单活跃实例部署；多机入口用反向代理或主备切换，同一时间只让一个实例执行编排动作。

## 5. 故障转移边界

| 场景 | 行为 |
|------|------|
| 单个推理端点失败 | Edge 重试其它健康上游；失败上游冷却 |
| 整个节点不可用 | 健康探测剔除；watchdog 尝试重启 Job |
| Job 崩溃 | watchdog 按 `max_restarts` 重启并等待 |
| Control 的 Edge 进程退出 | systemd 重启；`gateway ensure` 可恢复 |
| Control 主控宕机 | 用外部主备或反代接管入口；编排动作仍由活跃实例执行 |

## 6. 默认配置建议

```json
{
  "gateway": {
    "ingress": {
      "enabled": true,
      "kind": "edge",
      "strategy": "round_robin",
      "retries": 2,
      "cooldown_sec": 30
    }
  },
  "watchdog": { "enabled": true, "jobs": [], "interval_sec": 60, "max_restarts": 3, "failure_threshold": 2 }
}
```

这样新集群默认就有：单入口、健康感知 LB、请求级失败换上游、Job 自动重启；AI Gateway 在就绪时自动挂上。

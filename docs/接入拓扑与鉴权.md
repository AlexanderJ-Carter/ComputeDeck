# 接入拓扑与鉴权

第一次使用先看入门说明：[开始使用](开始使用.md)。本页给需要排障或做安全评估的人。

这里说明主控、被控、远程访问、鉴权和插件之间的关系。具体实现以 [安全加固](安全加固.md)、[远程接入](远程接入.md)、[VS Code 插件](vscode插件.md)、[打包与发布](打包与发布.md) 为准。

## 1. 拓扑角色

```text
┌──────────── 客户端 ────────────┐
│  浏览器 / VS Code·CodeLab / MCP Agent  │
└───────────────┬────────────────┘
                │  HTTP(S) · Bearer / Session / OIDC
                ▼
┌──────────── 主控 control ──────┐
│  UI :8787 · API · MCP · 调度/租约/入口  │
│  Ansible / SSH 出站到被控节点          │
└───────────────┬────────────────┘
                │  SSH（ansible_user / key）
                ▼
┌──────────── 被控节点 workers ──┐
│  GPU · nvidia-smi · Job 进程 · 推理端口 │
└────────────────────────────────┘
```

| 角色 | 职责 | 不负责 |
|------|------|--------|
| **主控** | 唯一的控制面：配置、调度、探活、入口、鉴权、助手 | 不要求本机有 GPU |
| **被控** | 运行 Job、暴露推理端口；由主控通过 SSH 管理 | 不运行控制面 UI |
| **客户端** | 人或 Agent 访问主控 | 不直接修改 `nodes.json` |

主控和被控之间靠 SSH 密钥与 inventory 建立信任；客户端访问主控时则走鉴权。

## 2. 访问路径（按推荐顺序）

| 场景 | 怎么连 `:8787` | 鉴权要求 | 典型用户 |
|------|----------------|----------|----------|
| A. 坐在主控上 | `http://127.0.0.1:8787` | 建议 password 或 OIDC；本机可自动读取 Token | CodeLab / SSH 登录主控 |
| B. 笔记本 → 主控 | `ssh -N -L 8787:127.0.0.1:8787 <control>` 后访问本机 8787 | 同 A | 日常运维 |
| C. IDE Remote SSH | 工作区在主控；插件 `apiBase=127.0.0.1:8787` | 自动读 `config/local/secrets/ui_api_token` | VS Code / Cursor / CodeLab |
| D. 团队内网 | Tailscale **serve**（仅 tailnet） | **必须** password 或 oidc | 多人共享 |
| E. 临时公网演示 | Tailscale funnel / Cloudflare quick | **强制**鉴权；`remote plan` 会阻塞未鉴权配置 | 演示 |
| F. 长期域名 | Cloudflare Tunnel + **Access（外层 SSO）** + 控制面 oidc/password | 两层：Access + 控制面 | 生产外网 |

默认情况下 UI 只绑 `127.0.0.1`，用 A、B、C 三种方式访问；需要从集群外接入时再加 D；公网只建议 E（临时）或 F（长期）。

端口转发属于基础设施，不是产品功能页。它的作用是把只监听回环地址的控制面接到浏览器。D/E/F 由「配置 → 远程接入」管理；A/B/C 用 SSH 或 IDE 自带的转发即可，页面里也会显示对应说明。

## 3. 鉴权矩阵

### 3.1 模式（`cluster.control.auth.mode`）

| 模式 | Web 登录 | API / MCP | 适用 |
|------|----------|-----------|------|
| `none` | 无 | 无 | 仅本机调试；`doctor` 会告警；**禁止**非回环绑定与公网 remote |
| `password` | Session Cookie | Bearer Token（`auth issue-token`） | 小团队默认 |
| `oidc` | 授权码 + PKCE → Session | 仍用 API Token（机器身份） | 企业 SSO / 统一登录 |

OIDC 可选 `allow_password_fallback`（默认关闭），并支持通过邮箱或 Groups 做白名单。

### 3.2 身份怎么用

| 调用方 | 凭证 | 存放位置 |
|--------|------|----------|
| 浏览器 | Session Cookie（HttpOnly） | 浏览器；插件可存进 SecretStorage |
| 脚本 / MCP / 插件 HTTP | `Authorization: Bearer` | `config/local/secrets/ui_api_token` 或 SecretStorage / 环境变量 |
| 被控节点 | 没有控制面账号，靠 SSH | `nodes.json` · ansible key |

插件在主控本机上的解析顺序是：`ui_api_token` 文件 → SecretStorage → `GPU_CONTROL_API_TOKEN` 环境变量。

### 3.3 SSO 和账号系统的边界（方向已定）

1. **控制面 SSO 用 OIDC**（已实现）：对接公司 IdP，例如 Okta、Keycloak，或兼容 OIDC 的企业微信、飞书。
2. **边缘 SSO 用 Cloudflare Access 或 Tailscale ACL**：只解决谁能访问域名，不替代控制面鉴权。
3. **不做**：自建账号系统；以 SAML 为主（如果 IdP 只提供 SAML，可在网关转换成 OIDC）；把被控节点纳入 OIDC。
4. **后续可以排期的改进**：IdP 预设模板、回调 URL 一键复制、OIDC 组映射到操作角色（只读 / 运维）、按用途拆分 Token（MCP 只读与部署分开）。

## 4. 客户端约定

| 客户端 | 连接方式 | 完整看板 / 助手 | 高频操作 |
|--------|----------|-----------------|----------|
| Web | A–F | 唯一的完整 UI，包含助手和公告 | — |
| VS Code 插件 | 优先 C；否则 B 加改 `apiBase` | 用 Simple Browser 或平台打开代理 URL；**不要**在 CodeLab Webview 里硬嵌 `/proxy/8787` iframe（常被 TCP 拒绝） | 工作台 / 集群树 / 终端 / 诊断 / 部署 |
| MCP Agent | HTTP + Token | 通过 `gc_*` | 同 API |

### 4.1 CodeLab / 网页版 IDE（主控本机，场景 C）

| 通道 | 走哪 | 免密 | 说明 |
|------|------|------|------|
| 插件树 / 工作台 / 命令 | 扩展宿主 → `127.0.0.1:8787` | 是，读 `ui_api_token` | 侧栏能刷新集群，说明这条通道正常 |
| 完整 Web 看板 | 浏览器 → CodeLab `…/proxy/8787/` | 否（Session，或再登录一次） | 用「接入说明 → Simple Browser / 平台打开」 |
| 被控节点 | 主控 SSH 出站 | 是，密钥 | 与 UI 密码无关 |

`asExternalUri(http://127.0.0.1:8787)` 会返回代理 URL。这个地址在系统浏览器或 Simple Browser 里通常可用，在扩展 Webview 的 iframe 里经常被拒绝。这是 IDE 对 Webview 网络的限制，不是控制面故障。

### 4.2 插件和网页的分工

插件提供工作台和接入说明，负责讲清拓扑与鉴权。完整看板和助手对话留在 Web，通过 Simple Browser 或 `openExternal(asExternalUri)` 打开。插件里不再实现一套完整 UI，也不依赖 Webview iframe 嵌 `/proxy/8787`。

### 4.3 方便、安全和性能之间的取舍

目标很具体：在主控本机上几乎不需要额外操作；访问范围扩大到内网或公网时，逐步增加验证；高频接口不经过 IdP 往返。

#### 四种凭证

| 凭证 | 形态 | 谁用 | 性能 | 安全要点 |
|------|------|------|------|----------|
| **A. 回环免密** | 无 Cookie；仅内核 peer 属于 `{127.0.0.1,::1}`，且显式允许 | 桌面单机调试 | 最快 | **禁止**非回环绑定；peer 从 TCP 读取，不信 `Host` 或 `X-Forwarded-For` |
| **B. 本机 Token** | `ui_api_token` 文件 → Bearer | 插件 / MCP / 脚本（在主控上） | 本地校验哈希，无外部请求 | 文件权限 0600；可轮换；不进 URL 和日志 |
| **C. 浏览器 Session** | HttpOnly Cookie（password / OIDC） | 完整 Web 看板 | 登录一次，之后本地验证 Session | TTL 有上限；CSRF 只用于写操作；禁止把长期 token 放进 URL |
| **D. 边缘身份** | Tailscale ACL / Cloudflare Access / 公司 SSO | 出网或多人使用 | 边缘终止连接，源站仍要 B 或 C | 外层身份**不能替代**控制面鉴权 |

ComputeDeck 目前支持 B、C（含 OIDC）以及 D 对应的远程接入文档路径。A 只对应 `auth.mode=none`，且必须绑定回环地址。

#### 各场景的选择

| 场景 | 推荐链路 | 为什么合适 |
|------|----------|------------|
| CodeLab / Remote 坐在主控 | 插件走 **B**（自动读 Token）；看板用 **票据交换** 换 Session，再走 **C** | API 高频路径不经过 IdP；代理隧道由 IDE 建立，避免坏掉的 iframe |
| 笔记本日常使用 | SSH `-L` 或 Tailscale **serve** → 仍走 **C/B** | 在网络上收窄到信任域，应用层不变 |
| 团队内网看板 | serve（仅 tailnet）+ 控制面 password/OIDC | serve 可以带身份头，源站仍绑 localhost，避免伪造请求头 |
| 长期公网 | Cloudflare Tunnel + **Access** + 控制面 OIDC | 两层分开：能访问域名和能调用 API 是两件事 |
| 被控 GPU 机 | **只走 SSH**，不另建账号 | 少一处暴露面，也保持直连性能 |

#### 插件打开看板：一次性票据（已实现）

插件在主控本机已经持有 **B. 本机 Token**。用户点「打开完整看板」时：

1. 插件调用 `POST /api/auth/exchange`（Bearer / Session 均可），服务端返回一张随机票据；
2. 插件把浏览器指向 `/auth/consume?code=…&next=/#/…`；
3. 服务端消费票据，写 HttpOnly Session Cookie，再 302 到目标页。

票据规则：

- 90 秒有效，只能消费一次，只存在进程内存里；
- `next` 只接受站内相对路径，拒绝 `//` 和外部 URL；
- code 不写磁盘；访问日志里的 `code=` 会被脱敏；
- 拿不到票据（未登录、旧版控制面、鉴权关闭）时自动退回普通看板地址，不会阻断。

这条链路解决的是「插件已经免密，网页大屏却还弹登录」；它不会让其他设备免密。直接在别的机器浏览器里输入网址，仍然需要 password / OIDC。

给新设备临时登录时，用 `gpu-control auth pair --ttl 300` 生成一张 5 分钟的一次性配对链接；链接同样走 `/auth/consume`，只能使用一次。它适合笔记本、临时演示和远程排障，不适合长期分发。

#### 不做的和暂缓的

- **不做**：在 CodeLab Webview 里把 `/proxy/8787` iframe 当主路径。隔离网络下常被 TCP 拒绝，业界也推荐 `asExternalUri` + `openExternal`。
- **不做**：每个 API 请求都去公司 IdP 校验。这样又慢又容易失败；OIDC 只在换取 Session 时发生。
- **不做**：把长期 Bearer 放进 URL，或做成常驻二维码。日志和 Referer 都可能泄漏。
- **暂缓**：Funnel 或裸公网。必须先有强 Session，并且 `remote plan` 继续拦截 `auth.mode=none`。
- **暂缓**：面向浏览器用户的 mTLS。它更适合机器身份和设备策略，不适合作为小团队的默认方案。

#### 后续可以做的改进（尚未实现）

1. **回环自动 Session**：仅当 peer 确实是回环地址且模式允许时，本地浏览器免登录。经代理进来的请求不算回环（CodeLab proxy 仍走票据交换或密码）。
2. **Scoped Token**：拆成 `read` 和 `deploy`，MCP 默认只读，减少 Agent 误操作的影响。
3. **设备码登录**：笔记本没有隧道时，可以参考 `gh auth login` 的 device flow，浏览器在本机、CLI 在远端。
4. **Serve 身份头**：团队内网时信任 Tailscale 用户头（源站必须绑定 localhost），再映射到只读或运维角色。

小结：插件在主控上走本地 Token，人看网页走 Session；从插件点开时用一次性票据把两者接起来。从集群外直接访问仍然同时要边缘身份和控制面身份；被控节点只走 SSH。

## 5. 交付与版本

| 产物 | 渠道 | 说明 |
|------|------|------|
| 控制面 | 源码包 · GHCR 镜像 | 仓库本身就是控制面 |
| 文档 | 控制面 `/help/` · 仓库 `docs/` · Pages `/docs/` | 根路径是演示页 |
| VS Code 扩展 | **VSIX**（Release / 内网分发）；之后可选上 Open VSX | **不发 npm**：编辑器扩展的分发单元是 VSIX，不是 npm 包 |
| Python | **不发 PyPI**（`package = false`） | 使用仓库或镜像 |

发版时四处版本号必须一致：`VERSION`、`pyproject.toml`、`extensions/vscode/package.json`，以及 `CHANGELOG.md` 里的 `## [x.y.z]`。日常开发允许扩展 CHANGELOG 先记 `1.2.x` 小步版本，打 tag 前用 `prepare_release` 收束到同一版本号。

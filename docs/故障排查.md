# 故障排查

从这三条入手，通常能快速定位：

```bash
gpu-control doctor                       # 配置与运行时
gpu-control diagnose check               # 一致性检测
gpu-control logs --limit 50              # 最近动作
```

## 1. UI 起不来 / 端口占用

```bash
cat state/ui.log
ss -lntp | grep 8787
cat state/ui.pid
```

- `cannot bind 127.0.0.1:8787`：端口被占用，先停旧进程或换 `cluster.control.ui_port`。
- `ui --background` 判断“已在运行”会校验 `/proc/<pid>/cmdline`，PID 复用不会误判。
- 停止：`kill $(cat state/ui.pid)`；服务端处理 SIGTERM 并清理 pid 文件。
- 远程访问不到：确认 `cluster.control.ui_host` / `GPU_CONTROL_UI_HOST` 与防火墙，
  或使用 `ssh -L 8787:127.0.0.1:8787 <control>`。

## 2. 401 / 登录失败

```bash
gpu-control auth status
curl -s http://127.0.0.1:8787/api/auth/status | jq .
```

- `password_configured=false`：`gpu-control auth set-password --generate --enable`。
- 脚本/MCP：`Authorization: Bearer $(cat config/local/secrets/ui_api_token)`。
- OIDC：`gpu-control auth oidc-check`；核对 IdP 回调地址与 `allowed_*`。
- 会话过期：重新登录或重新签发 token。

## 3. SSH / Ansible 失败

```bash
gpu-control exec --nodes <node> -- hostname
gpu-control node render
```

- 检查 `config/local/nodes.json` 的 `ansible_host`、`ansible_user`、`ansible_port`、
  私钥路径；`doctor` 会校验私钥存在。
- 首次连接 host key 未收录：临时 `ssh-keyscan` 或按[安全加固](安全加固.md)配置。
- 节点上 `python3` 路径不一致：用 `defaults.paths.python` / 节点覆盖。

## 4. 动作一直“执行中” / 卡住

- 动作串行执行，长任务会占用动作锁；看 `state/ui.log` 与 `gpu-control logs`。
- 确认没有重复的 `ansible-playbook`/`ssh` 残留：
  ```bash
  ps -ef | grep -E 'ansible|ssh' | grep -v grep
  ```
- `ui` 的 `run_cli` 有超时；超时会返回结构化错误，不会永久挂起。
- 若需要并发多任务，建议用队列（`gpu-control queue submit`）而不是同时点多个长动作。

## 5. GPU / 节点状态不对

```bash
gpu-control gpu refresh
gpu-control get nodes
gpu-control procs list --node <node> --refresh
```

- `resources.json` 由 `collect-resources.yml` 生成；失败时看 ansible 输出。
- 节点被隔离：`cat state/node_state.json`；`gpu-control node uncordon --name <node>`。
- 残留 Lease：`gpu-control lease list`，确认无进程后 `lease release --id ...`。

## 6. 统一入口 / 网关

```bash
gpu-control gateway status
gpu-control gateway ensure
gpu-control endpoints --refresh
```

- Edge 只能在控制面启动；worker 上误启会被拒绝。
- nginx 在 `kind=edge` 时不必安装；LiteLLM 是可选组件。
- 入口不通先确认端点健康（`gpu-control health`）与端口监听（`ss -lntp`）。

## 7. 终端连不上

- 页面终端依赖本地 `/static/vendor/xterm`；检查浏览器控制台是否有 404。
- WebSocket 路径 `/ws/terminal`；反向代理必须允许 Upgrade。
- SSH 参数与 `nodes.json` 一致；`gpu-control exec --nodes <node> -- hostname` 能通再开终端。

## 8. state 损坏 / 数据恢复

运行时会自动把无法解析的 JSON 移到同目录 `*.corrupt-<时间戳>`，并使用安全默认值。
恢复步骤：

```bash
ls state/*.corrupt-* 2>/dev/null
# 人工修复后覆盖回原名，或从备份恢复
```

写入已统一走「临时文件 + os.replace」，Lease 读改写有 `flock` 保护；并发改动请走 CLI / API，避免直接编辑 state 文件。

## 9. 日志与审计

| 文件 | 用途 |
|------|------|
| `state/ui.log` | UI 进程输出 |
| `state/watchdog.log` | 看门狗 |
| `state/runlog.jsonl` | CLI / 一键动作 / 检测修复 |
| `state/gateway/*` | 网关产物与状态 |

日志无限增长时交给 logrotate；`runlog.jsonl` 自动保留最近一段。

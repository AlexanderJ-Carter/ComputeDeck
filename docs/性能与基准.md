# 性能与基准

这里测的是 **控制面自身** 的开销，不是 GPU 推理性能。推理性能取决于模型、卡型、vLLM / TensorRT-LLM 等，应该用各自的 benchmark 工具测。

## 怎么跑

```bash
# 控制面在跑，且本机有 Token（或设 GPU_CONTROL_API_TOKEN）
gpu-control bench --n 20 --concurrency 8
gpu-control bench --json
```

也可以直接跑脚本：`python scripts/bench_control.py --base http://127.0.0.1:8787`。

脚本只依赖 Python 标准库，测三类东西：

- 控制面 API 的顺序延迟（p50 / p95 / p99）；
- `/api/health` 在固定并发下的吞吐；
- 静态资源 `app.js` 的 gzip 传输大小。

## 一组参考数据

主控本机、`127.0.0.1`、无 TLS、Python 3.11、4 节点（2 在线）：

| 接口 | 响应大小 | p50 | p95 |
|------|----------|-----|-----|
| `/api/health` | 56 B | 0.8 ms | 1.1 ms |
| `/api/auth/status` | 548 B | 2.4 ms | 2.5 ms |
| `/api/overview?light=1` | 66 KB | 3.5 ms | 3.8 ms（稳态；冷启动可能更高） |
| `/api/gateway/status` | 9.5 KB | 1.2 ms | 1.3 ms |
| `/api/jobs` | 11 KB | 13.8 ms | 14.8 ms |

并发测试：`/api/health`，8 个并发，约 **1,600–1,740 req/s**（两次采样，本机回环）。

静态资源：

| 资源 | 原始 | gzip | 节省 |
|------|------|------|------|
| `app.js` | 321,354 B | 83,507 B | 237,847 B（74%） |
| `style.css` | 149,026 B | 27,036 B | 121,990 B（82%） |

> 这些数字是单机回环、无 TLS 的结果，用来比较版本和发现回归，不适合直接当公网 SLA。反代、TLS、跨机房都会增加延迟。

## 建议看的指标

| 指标 | 建议阈值 | 说明 |
|------|----------|------|
| `/api/health` p95 | < 20 ms（本机） | 最基本存活探测 |
| `/api/overview?light=1` p95 | < 100 ms（本机） | 看板首屏数据 |
| 看板接口响应体 | < 100 KB | 超过就考虑分页/裁剪 |
| `app.js` gzip | < 100 KB | 现在约 83 KB |
| Edge 故障切换 | 一个 `cooldown_sec` 内 | 默认 30s，重试 2 次 |
| nginx 配置漂移 | 0 | `gateway status` 的 `nginx.in_sync` |
| doctor issues | 0 | 发布 / 交接前 |

## 已经做的性能优化

- 控制面 API 支持 gzip；`app.js` 传输从 321 KB 降到 83 KB。
- 看板用 `overview?light=1`，只取首屏需要的字段。
- 静态资源带版本查询串，避免缓存旧文件。
- Edge 上游池按间隔热加载，健康状态变化不需要重启。
- nginx 生成配置带 `keepalive`、`proxy_socket_keepalive`、`proxy_buffering off`、`proxy_next_upstream_tries 2`。
- nginx `--watch` 只在渲染结果变化时 reload，避免无意义抖动。
- 助手工具步骤完成后折叠，长对话不会因为几十行动作记录变得不可读。

## 怎么解读

- **API 延迟**：控制面没有在每个节点装 agent，SSH / Ansible 只在动作时发生；看板轮询走本地 state 和缓存，所以 p50 是毫秒级。
- **吞吐**：1,600+ req/s 是回环上的健康检查上限，不是生产要求；它的意义是控制面本身不会成为轮询瓶颈。
- **gzip**：第一次加载收益最大；之后靠缓存和 ETag。
- **不要用它比较模型吞吐**。推理性能看 `vllm bench`、`lm-eval`、你的业务请求分布。

## 复现和回归

每次改控制面 API 或静态资源，跑一次 `bench_control.py`，把 JSON 存进 `dist/` 或发布记录；对比 p95 和传输大小即可发现明显回归。GPU 推理的基准请单独维护，不要混在一起。

# 配置参考

查找顺序：`config/local/<name>` → `config/<name>` → 仓库根 `<name>`。  
本机场景写在 `config/local/`，`config/examples/` 提供中性模板。

变量占位符：

- `${paths.xxx}`：节点路径（`defaults.paths` + 节点覆盖），用于 Job 的 python/script/extra_args/env/docker。
- `${GPU_CONTROL_*}`：环境变量（如 `api_key_file`）。
- `~` / `$HOME`：按主控环境展开。

---

## cluster.json

| 字段 | 说明 |
|------|------|
| `name` | 集群名 |
| `strategy` | `inference-pool` / `multi-node` / 自定义 |
| `default_job` | 未指定时的默认 Job；缺省时选用 `shell-job` 或已注册的第一个 Job |
| `control.node/host/ui_host/ui_port` | 主控身份与 UI 监听 |
| `control.auth` | `mode` / `session_ttl_hours` / 密钥文件 / `oidc` |
| `api.base_port` | 端点池起始端口（默认 8000） |
| `api.ports_per_node` | 每节点端口数（默认 1；可被节点覆盖） |
| `api.health_path` / `sample_path` / `paths` | 健康与探测路径 |
| `api.auth_header` / `auth_env` / `api_key_file` | 推理 API 鉴权 |
| `gateway.ingress` | `enabled` / `bind` / `port` / `kind(edge\|nginx)` / `public_base_url` / `strategy` / `tls` |
| `gateway.model_name` / `litellm_model` | 网关与 LiteLLM 展示名 |
| `gateway.litellm_bin` | 可选 LiteLLM CLI 绝对路径；留空则查 PATH / `~/.local/bin` / `.venv/bin` |
| `gateway.litellm_database_url` | 可选 `postgres://…`；LiteLLM Admin UI / 虚拟密钥需要数据库，未配时只用 Master Key 调 `/v1` |
| `gateway.litellm_database_url_file` | 连接串文件（权限 600）；与上一项二选一，文件优先于环境变量 |
| `gateway.litellm_database_mode` | `external`（默认）/ `embedded`；`embedded` 时 `gateway start --kind litellm` 自动拉起内置 Postgres |
| `gateway.openai_proxy_dir` | 可选外部 LiteLLM 目录（含 `start_litellm.sh`）；留空即可 |
| `gateway.openai_proxy_port` | LiteLLM 监听端口（默认 4000） |
| `watchdog` | `enabled` / `jobs` / `interval_sec` / `max_restarts` / `failure_threshold` / `nodes` |
| `health.auto_refresh` | `enabled` / `interval_sec` / `api_stale_sec` / `gpu_stale_sec` / `gpu_min_interval_sec`；过期数据自动采集 |
| `assistant.auto_insight` / `auto_insight_interval_sec` | 异常时自动让 AI 做只读解读（默认开，30 分钟节流） |
| `scheduling` | `prefer_labels` / `avoid_labels` / `unit_gpus`（`deploy`/`gc_deploy` 省略 gpus 时必填） |
| `collaboration` | 团队协作说明（自由字段，不影响逻辑） |

运行态（非配置，主控 `state/`，flock 串行）：`leases.json`（占用登记）、`queue.json`（简易队列）、`node_state.json`（cordon）。语义见[手册 §6.2](手册.md) 与[生产部署 · state 契约](生产部署.md)。`gateway.ingress.strategy` 等勿与 `cluster.strategy` 混淆，见[高可用 · strategy 词汇表](高可用与负载均衡.md)。

## nodes.json

| 字段 | 说明 |
|------|------|
| `defaults.ansible_user/port/ssh_private_key_file` | 全局 SSH |
| `defaults.gpus_per_node` / `role` | 默认卡数与角色 |
| `defaults.paths` | `python` / `repo` / `model_root` / `workdir` / `cache` 等 |
| `control` | 主控主机元数据 |
| `nodes.<name>.ansible_host` | 必填 |
| `nodes.<name>.gpus_per_node/labels/role/note` | 节点元数据 |
| `nodes.<name>.paths` | 节点级路径覆盖 |
| `nodes.<name>.base_port/ports_per_node` | 节点级端点池覆盖（vLLM 单端口常用 `ports_per_node: 1`） |
| `nodes.<name>.api` | `base_port` / `ports_per_node` 的别名写法 |

## jobs/*.json

| 字段 | 说明 |
|------|------|
| `name` | Job 名（文件名/安装名） |
| `kind` | `service` / `train`（仅语义） |
| `gpus_per_node` | 每节点卡数 |
| `nproc_per_node` | 启动进程数；默认等于 `gpus_per_node` |
| `distributed` | 注入 `NNODES/NODE_RANK/MASTER_ADDR/MASTER_PORT/NPROC_PER_NODE/HOSTFILE` |
| `master_port` | 分布式主端口（默认 29500；Ray 可用 6379） |
| `runtime` | `process` / `docker` |
| `python` / `script` | process 模式的解释器与入口 |
| `extra_args` | 追加参数（支持 `${paths.*}`） |
| `env` | 额外环境变量（支持 `${paths.*}`） |
| `model` | 关联模型 id（展示/联动） |
| `docker.image/name/gpus/ports/volumes/env/command` | docker 模式 |
| `actions` | `start` / `stop` / `restart` / `status` / `wait` |

模板：`config/examples/*.example.json`；安装到 local：

```bash
gpu-control jobs templates
gpu-control jobs install --recommended          # 推理/训练/Ray/Docker 推荐包
gpu-control jobs install train-job --name sft
```

## models.json

| 字段 | 说明 |
|------|------|
| `models[].id` | 本地模型 id |
| `models[].repo` / `path` | 仓库与节点路径 |
| `models[].launch.job/extra_args` | 与 Job 联动 |
| `models[].verify.expect_files/min_bytes` | 校验规则 |
| `caches` | 缓存目录登记 |
| `defaults_paths` | 展示用路径 |

Token：`config/local/secrets/`（HF / ModelScope）。

## toolkits.json（可选）

覆盖内置工具栈同 `id` 的 `probe_import` / `probe_cli` / `install_pip` / bundle。  
内置含 torch / transformers / accelerate / deepspeed / llamafactory / peft / ray / vllm / openai。

## 环境变量

| 变量 | 作用 |
|------|------|
| `GPU_CONTROL_UI_HOST/PORT` | UI 监听（命令行 `--host/--port` 优先） |
| `GPU_CONTROL_LITELLM_PG_PORT` / `GPU_CONTROL_LITELLM_PG_DATA` | 内置 Postgres 端口与数据目录（默认 `5433` / `~/.local/share/computedeck/litellm-pg/data`） |
| `GPU_CONTROL_UI_SECURE` | HTTPS 终止后给 Cookie 加 Secure |
| `GPU_CONTROL_REQUIRE_AUTH` | `1` 时 doctor 把未鉴权升为失败 |
| `GPU_CONTROL_API_BASE/TOKEN` | MCP / 脚本访问 |
| `GPU_CONTROL_JOB_NAME/RUNTIME` | Job 运行时目录与日志 |
| `GPU_CONTROL_HEALTH_URL/HOST/PORT` | vLLM 就绪探测（可选） |
| `GPU_CONTROL_ALLOW_EDGE_ANYWHERE` | 允许非控制面启动 Edge（谨慎） |

## 迁移到新集群

1. 复制 `config/examples/{cluster,nodes,models}.example.json` 到 `config/local/`；
2. 改 control/nodes/api/paths/auth；
3. `gpu-control node render && doctor`；
4. 按需安装 Job 模板；
5. 每个集群各自维护 `config/local` 与 `state`，不把旧集群的本地状态直接拷过去。

# 生产部署

gpu-control 是**控制面**：一台 Linux 主控（CPU 即可）通过 SSH/Ansible 编排若干 NVIDIA GPU 工作节点。  
它默认不假设集群名、模型名、端口或业务栈；这些都在 `config/local/`。

## 1. 支持边界

| 组件 | 要求 |
|------|------|
| 主控 | Linux（推荐）或 macOS；Python 3.11+；`uv`；SSH 客户端；Ansible（`.venv` 内） |
| 工作节点 | Linux；NVIDIA GPU；SSH 免密登录；`nvidia-smi` |
| 可选 | Docker + NVIDIA Container Toolkit（`runtime: docker`）；vLLM / Ray / LLaMA-Factory 等按 Job 安装 |

不支持：Windows 工作节点、非 NVIDIA 采集、K8s/Slurm 编排放到控制面内。

## 2. 安装

```bash
git clone <repo> /opt/gpu-control
cd /opt/gpu-control
uv venv .venv
uv pip install -r requirements.txt
./examples/quickstart.sh
```

编辑 `config/local/cluster.json`、`config/local/nodes.json`（从 `config/examples/` 复制），然后：

```bash
gpu-control node render
gpu-control doctor
gpu-control ui --background     # 读 cluster.control.ui_host / ui_port
gpu-control watchdog --background  # 默认监控 default_job
```

`ui --background` 写入 `state/ui.pid` 与 `state/ui.log`。没有显式 `--host` 时优先读
`cluster.control.ui_host`；配置文件也没写则默认 **127.0.0.1**（安全默认）。

## 3. systemd（推荐）

### UI

```ini
# /etc/systemd/system/gpu-control-ui.service
[Unit]
Description=gpu-control UI
After=network-online.target

[Service]
Type=simple
User=gpu
WorkingDirectory=/opt/gpu-control
Environment=GPU_CONTROL_UI_HOST=127.0.0.1
Environment=GPU_CONTROL_UI_PORT=8787
Environment=GPU_CONTROL_UI_SECURE=1
ExecStart=/opt/gpu-control/.venv/bin/python /opt/gpu-control/web/server.py
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target
```

> 需要内网直接访问时才把 `GPU_CONTROL_UI_HOST` 改为 `0.0.0.0`，并确保已启用鉴权 + 防火墙。

### Watchdog

```ini
# /etc/systemd/system/gpu-control-watchdog.service
[Unit]
Description=gpu-control watchdog
After=gpu-control-ui.service

[Service]
Type=simple
User=gpu
WorkingDirectory=/opt/gpu-control
ExecStart=/opt/gpu-control/bin/gpu-control watchdog --job <job-name> --interval 60 --max-restarts 3
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now gpu-control-ui gpu-control-watchdog
curl -fsS http://127.0.0.1:8787/api/health
```

## 4. 端口与入口

| 端口 | 用途 |
|------|------|
| `8787` | 控制面 UI/API（默认） |
| `18080` | 可选统一入口 Edge（`cluster.gateway.ingress`） |
| `8000+` | 推理端点池（`cluster.api.base_port`） |
| `6379/8265` | 可选 Ray GCS / Dashboard |

TLS 有两种方式：

1. **控制面 HTTPS 由上层反代终止**（nginx / 云 LB），设置 `GPU_CONTROL_UI_SECURE=1`；
2. **推理统一入口**使用 `cluster.gateway.ingress.tls.*`，由 Edge/nginx 产物承载。

不要把控制面 UI 和数据面入口混在同一个未鉴权域名下。

## 5. 日志与状态

| 路径 | 内容 |
|------|------|
| `state/ui.log` | UI 进程输出（`ui --background`） |
| `state/runlog.jsonl` | CLI / 一键动作 / 检测修复审计日志（`gpu-control logs`） |
| `state/watchdog.log` | 看门狗输出 |
| `state/leases.json` / `queue.json` / `node_state.json` | 调度状态（原子写 + 文件锁） |
| `state/ingress*.json` | 统一入口状态 |

日志轮换建议交给 logrotate；`runlog.jsonl` 有 2MB 自动裁剪。

## 6. 发布前检查清单

- [ ] `gpu-control doctor` 通过；鉴权已启用（`password` 或 `oidc`）
- [ ] `GPU_CONTROL_UI_HOST` 不是无鉴权的 `0.0.0.0`
- [ ] `config/local/`、`state/`、`inventory.ini`、`resources.json`、`snapshots/` **不随产物分发**
- [ ] `.venv` 依赖锁定（提交 `uv.lock` 或记录版本）
- [ ] `./scripts/check.sh` 通过
- [ ] `python scripts/smoke_ui.py` 通过（带 token）
- [ ] 备份 `config/local/` 与 `state/*.json`
- [ ] 文档站 `/help/` 已构建（`gpu-control docs build`）

干净的源码包：

```bash
git archive --format=tar.gz --prefix=gpu-control/ HEAD -o /tmp/gpu-control.tgz
# 该命令不会包含 config/local、state、inventory.ini 等 gitignore 文件
```

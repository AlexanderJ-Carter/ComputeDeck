# 使用指南

## 安装（Control 节点）

```bash
cd /path/to/gpu-control
uv venv .venv && uv pip install -r requirements.txt
./examples/quickstart.sh          # 生成 config/local + 链到 PATH
# 编辑 config/local/{cluster,nodes}.json 与 jobs/
gpu-control doctor
gpu-control ui --background       # :8787
```

配置查找顺序：`config/local/` → `config/` → 仓库根。密钥与内网 IP 只放 `config/local`（gitignore）。

## 核心能力（通用）

```bash
gpu-control overview              # GPU + 占用总览
gpu-control metrics               # CPU / 内存 / 负载
gpu-control get nodes
gpu-control exec --nodes all -- 'nvidia-smi -L'
gpu-control free --node NAME --cordon
gpu-control node uncordon NAME
gpu-control doctor
```

Web：
- **一键运维**：就绪 / 连通 / 体检 / 刷新  
- **终端**：xterm 交互 SSH（真 PTY）  
- **批量输出**：远程命令的结构化结果（不是交互 shell）

## 工作负载（任意 Job）

复制示例并改路径：

```bash
cp config/examples/decider.example.json config/local/jobs/myjob.json
gpu-control start myjob --nodes all
gpu-control status myjob
```

字段见 [jobs/README.md](../jobs/README.md)。Job 可以是推理服务、评测脚本、数据预处理——只要远端脚本支持约定动作。

## 可选：推理模块

当 Job 暴露 HTTP API 时：

```bash
gpu-control endpoints
gpu-control health                # 默认各节点本地 /health
gpu-control deploy myjob --gpus 4
```

## 可选：模型工具

在 `config/local/models.json` 声明共享盘缓存根（见 `config/examples/models.example.json`）：

```bash
gpu-control models check          # 各节点检查路径/磁盘
gpu-control models pull --name <id>   # 若节点有 huggingface-cli 则拉取
```

Web「一键运维」里也有「模型缓存检查」。

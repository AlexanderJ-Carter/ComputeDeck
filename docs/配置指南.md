# 配置指南

从空仓库到“能用”的最短路径。字段细节见 [配置参考](配置参考.md)，命令细节见 [手册](手册.md)。

## 1. 最小配置

```bash
cp -n config/examples/cluster.example.json config/local/cluster.json
cp -n config/examples/nodes.example.json config/local/nodes.json
```

改 `config/local/cluster.json`：

- `control.node` / `control.host`：主控身份；
- `api.base_port` / `api.ports_per_node`：推理端口范围；
- `scheduling.unit_gpus`：按卡数部署时的调度单位。

改 `config/local/nodes.json`：

- `defaults.ansible_user` / `ansible_ssh_private_key_file`；
- 每个节点的 `ansible_host`、`gpus_per_node`、`labels`；
- 节点路径不一致时写节点级 `paths`。

然后：

```bash
gpu-control node render
gpu-control doctor
```

`doctor` 0 issues 再做下一步。

## 2. 鉴权

本机调试可以先用 `none` + SSH 隧道；只要绑非回环地址或对外，就必须开鉴权：

```bash
gpu-control auth set-password --generate --enable
gpu-control auth issue-token
```

- 浏览器：密码或 OIDC；
- 插件 / 脚本 / MCP：API Token；
- 企业登录：在配置页「鉴权与访问」填 OIDC Issuer / Client ID / Secret；
- 远程设备临时登录：`gpu-control auth pair --ttl 300`，5 分钟一次性链接。

免密范围见 [开始使用 · 哪些地方需要登录](开始使用.md#_4)。

## 3. 入口

### 3.1 内置 Edge（默认，最省事）

```json
{
  "gateway": {
    "ingress": {
      "enabled": true,
      "kind": "edge",
      "bind": "0.0.0.0",
      "port": 18080,
      "strategy": "round_robin"
    }
  }
}
```

```bash
gpu-control gateway ensure
```

### 3.2 LiteLLM 做唯一节点 LB

```json
{
  "gateway": {
    "litellm_upstream": "nodes",
    "openai_proxy_port": 4000,
    "ingress": { "proxy_to": "http://127.0.0.1:4000" }
  }
}
```

```bash
gpu-control gateway start --kind litellm
gpu-control gateway start --kind edge
```

Admin UI / 虚拟密钥需要 Postgres：`gpu-control gateway litellm-db init`。

### 3.3 nginx

```json
{
  "gateway": {
    "nginx": {
      "apply_path": "/etc/nginx/conf.d/computedeck.conf",
      "test_cmd": "sudo nginx -t",
      "reload_cmd": "sudo nginx -s reload",
      "sync_interval_sec": 15,
      "ui_url": "http://127.0.0.1:9000"
    }
  }
}
```

```bash
gpu-control gateway nginx --apply
gpu-control gateway nginx --watch --background
```

多台 nginx 共用配置时，控制面机器正常 `--watch`，其他节点用 `--reload-only`。Nginx UI 共存方式见 [入口分层与 nginx](入口分层与nginx.md#44-nginx-ui)。

### 3.4 TLS

```bash
gpu-control tls init --domain api.example.com
gpu-control tls check
```

自签适合内网；公网换公司 CA / ACME。

## 4. 远程接入

| 场景 | 做法 |
|------|------|
| 主控本机 | 直接 `http://127.0.0.1:8787` |
| 笔记本日常 | `ssh -N -L 8787:127.0.0.1:8787 <control>` |
| IDE Remote SSH / CodeLab | 工作区在主控；插件自动读本机 Token |
| 团队内网 | Tailscale serve（仅 tailnet）+ 控制面密码/OIDC |
| 长期公网 | Cloudflare Tunnel + Access + 控制面 OIDC |

Tailscale / Cloudflare 的启停见 [远程接入](远程接入.md)。

## 5. Job 与模型

```bash
gpu-control jobs templates
gpu-control jobs install --recommended
gpu-control models pull --name org/model --register
```

业务 Job 放 `config/local/jobs/`，不要改内置模板；字段见 [配置参考 · jobs](配置参考.md#jobsjson)。

## 6. AI / MCP

```bash
uv pip install -r requirements-mcp.txt
gpu-control auth issue-token
```

把 `config/examples/mcp.cursor.json` 或 `mcp.claude-code.json` 复制到对应客户端，改成主控绝对路径和 Token。

网页小助手在「配置 → AI / MCP」里填 Base URL / 模型 / Key；先连通探测，再拉模型列表。

## 7. 验收

```bash
gpu-control doctor
gpu-control diagnose check
gpu-control gateway status
gpu-control bench --n 20 --concurrency 8
```

- doctor 0 issues；
- 看板健康分正常；
- 入口 `/_gpu_control/health` 可达；
- nginx `in_sync=true`（如果启用）；
- TLS `ready=true`（如果启用）；
- 插件侧栏能刷新，完整看板从插件打开不弹密码。

## 8. 常见配置错误

| 现象 | 检查 |
|------|------|
| `doctor` 说 inventory 缺节点 | `gpu-control node render` |
| SSH 失败 | `defaults.ansible_ssh_private_key_file`、节点 `ansible_port` |
| 插件连不上 | `computedeck.apiBase`、`config/local/secrets/ui_api_token` |
| 看板打开要密码 | 是否从插件打开；票据是否过期 |
| nginx 不生效 | `gateway.nginx.apply_path` 是否被 include；`gateway status` 的 `in_sync` |
| LiteLLM 没有节点 | `litellm_upstream=nodes` 后重新 `gateway render` |
| 入口重复 LB | 只保留 LiteLLM 或 Edge 一层；看 `gateway status.layering` |

# 安全加固

控制面能对 GPU 节点执行命令，按高权限系统设计加固即可。

## 1. 鉴权与绑定

```bash
gpu-control auth set-password --generate --enable
gpu-control auth issue-token
gpu-control auth status
```

- `cluster.control.auth.mode`：`none` / `password` / `oidc`。
- 生产环境使用 `password` 或 `oidc`；`none` 配合 SSH 隧道做内网调试时，`doctor` 会提示开启鉴权。
- 硬性检查：`GPU_CONTROL_REQUIRE_AUTH=1 gpu-control doctor`。
- UI 默认绑定 `127.0.0.1`；需要内网直连时设置 `cluster.control.ui_host = "0.0.0.0"` 或
  `GPU_CONTROL_UI_HOST=0.0.0.0`，并配合防火墙。**未启用鉴权时进程会拒绝绑定非回环地址**
  （容器镜像显式设置 `GPU_CONTROL_ALLOW_INSECURE=1`；宿主机可用同名环境变量在受信网络临时绕过）。
- 常用入口：`ssh -L 8787:127.0.0.1:8787 <control>`。

## 2. Token 与 Cookie

- API Token 存 `config/local/secrets/ui_api_token`，权限 `600`；配置页「生成 / 轮换 Token」只显示一次，轮换即失效旧 Token。
- OIDC / 免密登录在配置页「鉴权」面板配置；IdP 回调 `http(s)://<control>:8787/api/auth/oidc/callback`，保存后可直接「测试 OIDC」。
- Session Cookie 为 `HttpOnly` + `SameSite=Strict`；HTTPS 终止后设置 `GPU_CONTROL_UI_SECURE=1`。
- WebSocket 终端只接受 Session Cookie 或 `Authorization` 头；**不再接受 URL 里的 `?access_token=` / `?token=`**（会进入浏览器历史、代理日志）。浏览器外请用带 Cookie 的会话，或在请求头里带 Bearer。
- OIDC 使用授权码 + PKCE；`allow_password_fallback` 默认关闭。
- OIDC 默认 `require_userinfo=true`（走 userinfo，校验签名而不只解码 `id_token`）；pending state 文件 `0600`。
- 密码登录按来源 IP 节流（5 分钟内失败过多返回 429）。
- 响应带 `CSP` / `X-Frame-Options: DENY` / `nosniff`；`secrets` 建议 `700`，密钥文件 `600`（doctor 会检查）。

## 3. 高危接口

以下接口等价于远程命令执行/节点破坏，务必只对可信用户开放：

`/api/exec`、`/api/run-python`、`/api/procs/kill`、`/api/free`、
`/api/deploy`、`/api/jobs/{name}/action`、`/api/config/*`、`/api/gateway/start|stop`。

建议：

- 使用独立 API Token，按环境区分；
- 在外层反代限制来源 IP；
- 审计：`gpu-control logs` 记录 CLI / 一键动作；如需记录 HTTP principal，请在反代层记录。

## 4. SSH 主机密钥

当前默认 `StrictHostKeyChecking=no`（方便首次接入），这会扩大 MITM 风险。生产建议：

1. 先在维护窗口用 `ssh-keyscan` / 首次人工登录把节点公钥写入主控 `~/.ssh/known_hosts`；
2. 在 `ansible.cfg` 中改用：
   ```ini
   [defaults]
   host_key_checking = True
   [ssh_connection]
   ssh_args = -o ControlMaster=auto -o ControlPersist=60s -o StrictHostKeyChecking=accept-new
   ```
3. 定期核对 `known_hosts` 与 inventory 主机。

> 修改前先在测试集群验证，避免生产节点因 host key 未收录而批量失败。

## 5. 网络与 TLS

- 控制面 UI 与推理入口分开；公网访问前开启鉴权并收紧绑定与防火墙。
- 推理入口 TLS：`cluster.gateway.ingress.tls.*`，证书放 `config/local/secrets/`（600）。
- 反代层建议加：
  - `Content-Security-Policy`（控制台会自行加载同源静态资源）；
  - 访问日志与来源 IP 限制；
  - 请求体大小限制（服务端已限制 8MB）。

## 6. 文件权限

```bash
chmod 700 config/local/secrets
chmod 600 config/local/secrets/*
chmod 600 config/local/*.json   # 含内网 IP / 路径
```

`config/local/`、`state/`、`inventory.ini`、`resources.json`、`snapshots/` 均被 gitignore；
若用 tar/rsync 交付，务必排除这些路径（见[生产部署](生产部署.md)）。

## 7. 依赖与供应链

- 本仓库不加载任何外部 CDN（xterm 已本地化）。
- 建议提交 `uv.lock`（或记录 `requirements` 版本）以保证可复现。
- 工具栈安装会执行 `pip install`；请在受控网络/镜像内进行，并关注 vLLM / DeepSpeed 与 torch 的版本匹配。

## 8. 安全默认值速查

| 项 | 默认 | 生产建议 |
|----|------|----------|
| UI 绑定 | `127.0.0.1` | 保持或反代 |
| 鉴权 | 由 cluster 配置决定 | `password` 或 `oidc` |
| Host key | `no` | `accept-new` / `yes` |
| 控制面 HTTPS | 无 | 反代终止 + `GPU_CONTROL_UI_SECURE=1` |
| exec/run-python | 已登录用户可用 | 限来源 IP / 独立 token |

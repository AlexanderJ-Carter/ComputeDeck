# 部署总览

部署时只需要三部分：一台主控、若干 GPU 节点和一个对外推理入口。
推荐让 LiteLLM 直连节点做负载均衡；如果需要域名或 TLS，nginx 或内置 Edge 挡在 18080 前面。

装完后打开 UI `:8787`，或先读 [上手手册](手册.md)。

## 0. 整体结构

```
使用者 ──► 控制面 :8787（Web / CLI / MCP）
                │
                ├─ SSH / Ansible ──► GPU 节点（Job、模型、GPU）
                │
业务客户端 ──► LiteLLM :4000 ──► 节点 GPU 端口 30000+
                ▲
                └─ 可选：nginx / Edge :18080（TLS / 域名 / 网页）
```

| 地址 | 作用 |
|---|---|
| `:8787` | 控制面 Web / API（运维入口，默认只绑回环） |
| `:4000` | LiteLLM：唯一节点 LB + 模型名 / 虚拟密钥 / 预算 / Admin |
| `:18080` | 前置反代：nginx 或内置 Edge → LiteLLM（TLS/域名） |
| `30000+` | 节点推理端口，只给 LiteLLM 当上游 |

## 1. 选择拓扑

| 场景 | 节点 LB | 18080 | 配置 |
|---|---|---|---|
| 需要虚拟密钥 / 预算 / 统一模型名（推荐） | LiteLLM | 可选 nginx / Edge → 4000 | `litellm_upstream: "nodes"` |
| 轻量部署：只要原始 HTTP 入口 | Edge | Edge 监听 18080 | `litellm_upstream: "edge"` |
| 需要 443/TLS/域名 | LiteLLM | nginx → 4000 | `nginx_upstream: "litellm"` |

## 2. 安装主控

```bash
git clone https://github.com/AlexanderJ-Carter/ComputeDeck.git /opt/gpu-control
cd /opt/gpu-control
uv venv .venv && uv pip install -r requirements.txt
cp -n config/examples/cluster.example.json config/local/cluster.json
cp -n config/examples/nodes.example.json   config/local/nodes.json
```

编辑 `config/local/cluster.json`：

- `control.host` / `ui_host` / `ui_port`
- `gateway.litellm_upstream: "nodes"`
- `gateway.openai_proxy_port: 4000`
- `gateway.ingress.proxy_to: "http://127.0.0.1:4000"`（用 18080 做前置时）

编辑 `config/local/nodes.json`：节点地址、GPU 数、SSH 端口/用户/私钥覆盖、`paths`。  
然后：

```bash
gpu-control node render      # 生成 inventory
gpu-control doctor           # 配置 / SSH / 端口 / 权限检查
```

## 3. 鉴权

```bash
gpu-control auth set-password --generate --enable
gpu-control auth issue-token          # MCP / 脚本用
gpu-control auth status
```

UI 只绑 `127.0.0.1` 时用 SSH 隧道访问：

```bash
ssh -N -L 8787:127.0.0.1:8787 <control>
```

需要内网直连时设 `control.ui_host: "0.0.0.0"`，并确认鉴权已开启；服务在无鉴权 + 非回环绑定时会拒绝启动。

配置 → 「鉴权与访问」分页还提供：

- **OIDC / 免密登录**：填 Issuer、Client ID、Client Secret 文件、允许邮箱 / Claim / Scopes；IdP 回调填 `http(s)://<control>:8787/api/auth/oidc/callback`；保存后可点「测试 OIDC」。
- **API Token**：生成 / 轮换或清除脚本、MCP 使用的 Bearer Token。新 Token 只显示一次，轮换后旧 Token 立即失效。

## 4. 入口：LiteLLM 单层

### 4.1 LiteLLM 与内置 Postgres

```bash
/usr/bin/python3 -m pip install --user pgserver==0.1.4   # 一次性
gpu-control gateway litellm-db init                     # 建库 + DATABASE_URL
gpu-control gateway litellm-db status
```

`gateway.litellm_database_mode: "embedded"` 时，`gateway start --kind litellm` 会自动拉起 Postgres。  
已有外部 Postgres 时改配 `gateway.litellm_database_url_file`，跳过 `litellm-db init`。

### 4.2 生成并启动

```bash
gpu-control gateway render
gpu-control gateway start --kind litellm
gpu-control gateway start --kind edge      # 使用 18080 前置时
```

生成的 `state/gateway/litellm-model-list.yaml`：

- 启用 `litellm_upstream: "nodes"` 时，每个节点端口一个 deployment；
- 重试 / 冷却 / 路由策略由 LiteLLM router 统一负责；
- Edge / nginx 不再对节点做第二套 LB。

### 4.3 验证

```bash
gpu-control gateway status
curl -s -H "Authorization: Bearer $(cat config/local/secrets/litellm_master_key)" \
  http://127.0.0.1:4000/v1/models
```

LiteLLM Admin：`http://<control>:4000/ui`，用户名 `admin`，密码 = Master Key。  
虚拟密钥、预算、模型页都在 Admin 内管理；登录与虚拟密钥依赖第 4.1 步的数据库。

## 5. 节点、Job 与模型

```bash
gpu-control jobs install --recommended
gpu-control deploy <job> --gpus 4
gpu-control models list
gpu-control toolkits probe
```

Web 控制面提供同样的功能：节点页负责隔离、腾空和终端，任务页放 Job、队列和租约，模型页负责拉取和校验。

## 6. 更新主控

```bash
CONTROL_HOST=<control> ./scripts/deploy_control.sh
```

脚本流程：备份远端 `config/local` + `state` → 同步工作树（保留配置/状态）→ 同步 `/help/` 构建产物 → 重启 UI → 健康检查。

工作树同步会跳过 `state/`、`config/local/`、`snapshots/`、`inventory.ini`、`resources.json`：后两者是主控按 `nodes.json` 生成的运行时产物，不能被开发机的旧文件覆盖。若节点清单变化，请在主控执行 `gpu-control node render` 与 `gpu refresh`。

| 变量 | 作用 |
|---|---|
| `SKIP_BACKUP=1` | 跳过 `~/gpu-control-backup-<ts>.tar.gz` |
| `RESTART_GATEWAY=1` | 同步后 `gateway ensure`（改了 LiteLLM / Edge / nginx 时用） |
| `RESTART_WATCHDOG=1` | 同步后重启 watchdog |
| `CONTROL_DIR=...` | 远端目录不是 `~/gpu-control` 时指定 |

回滚：解压对应备份到远端目录，再重启 UI / gateway。

## 7. 配置检查与 AI 指导

- 配置页改为左侧分页，一次只显示一页内容：
  - **配置**：基础连接（SSH + 集群策略）· 节点清单 · Job 模板 · 巡检与守护 · 登录与鉴权（密码 / OIDC / Token）· 远程接入（Tailscale / Cloudflare / 端口）
  - **检查与接入**：就绪检查 · 日志与诊断 · AI / MCP
  - **参考**：文档与 API · 高级配置
- 配置分页带就绪状态点；「就绪检查」汇总主控/鉴权、SSH/节点、Job/模型、入口/LiteLLM、AI/MCP，可跳回对应分页，或点「重新检测」。
- 「登录与鉴权」可直接设置 / 轮换管理员密码、配置 OIDC 与 API Token；「日志与诊断」查看 UI / watchdog / Edge / LiteLLM / Cloudflare 日志尾与动作审计，无需登录主机。
- 配置 → AI / MCP：API 测试、Token 生成/轮换、MCP 配置复制、AI 助手设置。
- 「让 AI 指导」把步骤状态交给助手，读取 setup / overview / doctor 后给出下一步。

## 8. 自动化巡检

- **节点探活**：后台每 60 秒 TCP 探活，离线节点排除出调度。
- **健康数据**：API / GPU 快照过期时自动采集（`cluster.health.auto_refresh`）。
- **AI 只读解读**：异常时把 overview / notices / diagnose 交给 AI 生成建议（30 分钟节流，`cluster.assistant.auto_insight`）。
- **Watchdog**：按 `watchdog.jobs` 保活默认 Job。

## 9. 发布前检查

```bash
./scripts/check.sh
gpu-control doctor
gpu-control gateway status
```

- [ ] `config/local/`、`state/`、`inventory.ini`、`resources.json` 不随产物分发
- [ ] 鉴权已开启；Cookie 在 HTTPS 后设 `GPU_CONTROL_UI_SECURE=1`
- [ ] `/help/` 已构建（`gpu-control docs build`）
- [ ] 备份 `config/local/` 与 `state/*.json`

## 10. 排查入口

| 现象 | 先看 |
|---|---|
| UI 打不开 | `state/ui.log`、`GPU_CONTROL_UI_HOST/PORT`、防火墙 |
| 18080 502 | `gateway status` 的 `layering`；`ingress.proxy_to` 是否指向 4000 |
| LiteLLM 登录报 DB | `gateway litellm-db status`；`gateway status \| jq .litellm.database` |
| 模型没流量 | `state/gateway/litellm-model-list.yaml` 是否为逐节点 deployment |
| 节点连不上 | `gpu-control doctor`；节点 `ansible_port/user/key` 覆盖 |
